# Active catalog V1.3

`pnpm catalog:sync` requires a unique `OTHERBRIDGE_EVIDENCE_ROOT`. It makes one bounded current TVL read, validates finite positive mainnet entries, maps canonical numeric chain identities or stable discovery slugs, merges aliases and duplicates, and preserves the explicit ONEchain entry. Invalid rows are counted; a malformed envelope or empty result cannot replace the previous snapshot. The command writes raw observation, timestamp/hash, normalized catalog and deterministic diff, then updates only the cached snapshot. It never commits or enables financial capabilities.

TVL is a discovery signal. Catalog presence, wallet compatibility, portfolio coverage, quote infrastructure and a current valid route are separate. Unknown chains remain searchable with neutral local logos and unsupported actions. The route adapter owns financial chain/token identity. New metadata cannot create signing or execution support. Published counts are timestamped observations, never a fixed product count.

Server observations have a five-minute bounded cache and deduplicated refresh. A failed refresh returns the previous snapshot with stale state. Networks ranks detected holdings first, route infrastructure next, then TVL. The selector and Networks page virtualize their rows and search the complete catalog. Recently used IDs are stored locally. No testnet acquires TVL-based financial eligibility.

Actual source, endpoint, terms and provenance are in INTERNAL/V13_PROVIDERS.md. Existing curated network/logo assets are preserved; unknown icons use the inert geometric fallback.
