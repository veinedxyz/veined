# Read-only route data research

Otherbridge reads current chain/tool/connection/token/quote/status data through the existing server adapter. This public document describes product behavior. The real dependency identities, licenses and provider source links are only in the [technical record](INTERNAL/THIRD_PARTY_NOTICES.md). The architecture and provider selection were not changed in this text repair.

The SDK v4 client configuration is only on the server. ChainTypes EVM, SVM, UTXO, MVM, TVM, STL; large network IDs are kept as strings. The chain/address metadata in the Connections response is completed with real token data when needed. The internal fee collection step appears in the technical review as the neutral "Route service fee"; unknown tools are not accepted. Real bridge/protocol names are disclosed in the technical route review.

Official read-only REST GET reads in the existing adapter are bounded by 4 MB, 10 seconds, DNS pinning, redirect rejection and runtime schema validation. It is not claimed that the SDK quote actions are called directly. There is no execution provider; preload/version probe is disabled. In earlier evidence the public API worked without a key; there is no key, nor any integrator fee collection by Otherbridge. Quotes may include real bridge/protocol service and gas costs. A temporary error tied to the public quota, or the absence of a route, is not shown as success.

The public metadata logos of the 76 networks are stored as safe local SVGs. No brand approval by the network owner is claimed. The source URL, SHA-256, MIME, byte size and the derived ambient color note are in the existing asset-sync record. The earlier official ONE/BNB icons are preserved. Logo geometry/color does not change; the ambient palette is not a guarantee of official brand color. There is no claim of transfer of brand rights, partnership or sponsorship.

The earlier source research and the original byte copies of the old public texts are preserved in the internal historical archive. They are not current product text or a new interpretation of the user instructions. The results and dates of the new read-only tests and the working tree checkpoint are stated separately in the current handoff.
