# V1.17 hosting decision and secret custody

Status: **OWNER_INPUT_HOSTING / DECISION_REQUIRED / EXECUTION_CLOSED**. This is an architecture and procurement packet; no account, resource, deployment, secret or DNS record was created. Scope is the existing Next.js app, Data API, PostgreSQL, persistent indexers/RPC-health workers and internal monitoring.

The actual private stack in `infra/staging/compose.yaml` runs app `:3101`, Data API `:3200`, PostgreSQL 17, indexer, RPC-health, ops exporter, Caddy, Prometheus, Alertmanager and Grafana. Long-running memory caps total **5,248 MiB (5.125 GiB)**, or **6,016 MiB (5.875 GiB)** while the 768 MiB migration job runs. Aggregate CPU ceilings total 10 vCPU; they are per-service ceilings, not measured simultaneous demand. Moving PostgreSQL out leaves 4,224 MiB of long-running caps and 8 vCPU ceilings on the app/worker host. Existing rehearsals prove local restore/rollback behavior; they do not prove production throughput, sizing or SLA.

All patterns require exact-host TLS ingress, streaming responses without proxy buffering, 10–30 second graceful drains, read-only container roots with explicit writable cache/health storage, durable PostgreSQL limiter and indexer leases, non-public metrics/monitoring, off-host backups, and rollback to an approved image plus compatible DB schema. Do not use the local-only staging Compose as a public deployment file. Static export cannot supply the current server API/proxy/workers. Current [Next.js self-hosting guidance](https://nextjs.org/docs/app/guides/self-hosting) recommends a reverse proxy and documents streaming, runtime env and multiple-instance cache/build requirements; the installed `node_modules/next/dist/docs/01-app/02-guides/self-hosting.md` was also read.

Keep app/worker HTTPS and Titan WSS outbound-only, with no public WebSocket listener invented. Providers/RPCs retain reviewed allowlists and read-only transports. Reserve a stable egress IP where provider firewall policy requires it; record it in owner-controlled configuration, not as a new credential. Keep DB `5432`, metrics `3291–3293`, Prometheus, Alertmanager and Grafana private. Production alert receiver, incident owner, support window and backup custodian must be named. No alert was sent by this milestone.

Before host activation, owner accepts explicit recovery targets. Proposed starting targets for quotation: database RPO ≤15 minutes with PITR, recovery RTO ≤4 hours, daily independent encrypted export, 30-day retention, monthly isolated restore test. These are proposed requirements, not achieved SLOs. [PostgreSQL 17 backup documentation](https://www.postgresql.org/docs/17/backup.html) distinguishes dumps, filesystem backups and WAL/PITR; a successful managed backup status is not a restore proof. Preserve the existing tested append-only witness and migration-checksum policies. Rollback must not silently downgrade a migrated database; restore into a new isolated database if schema compatibility cannot be proven.

Secret custody contract for every option:

- No secret value in Git, source, Docker build ARG/layer, browser `NEXT_PUBLIC_*`, review ZIP, screenshots, shell history, traces, support tickets or logs. `NEXT_PUBLIC_PRIVY_APP_ID` is a public identifier, not provider API-key storage. Secret values never accompany a validation receipt.
- Separate staging/production accounts, keys, roles and storage namespaces. Grant app only its API DB role, provider credentials, pseudonym key and metrics token; workers only their required indexer/RPC secrets; monitor only aggregate-reader/metrics; backup only backup DB credential and encryption operation. Migration owner is a short-lived non-superuser role. Existing app/Data API role sharing must be explicitly assessed by the independent audit and production operator.
- Option A root-only file: `/etc/otherbridge/production.env`, root-owned `0600`, parent `0700`, outside repository/backups/image contexts; service supervisor injects runtime environment. Do not print it or run `docker inspect` into evidence. Docker/host administrators have equivalent secret access and require named membership. [Docker daemon access](https://docs.docker.com/engine/security/protect-access/) must be restricted accordingly.
- Docker mounts for A/B: grant each Linux container only its named `/run/secrets/<name>` files. [Compose secrets](https://docs.docker.com/compose/how-tos/use-secrets/) are bind-mounted files, not a standalone encrypted vault. Current app config reads environment values; mounting a file alone does not configure it and `_FILE` support must not be assumed. Use the chosen supervisor/secret service's reviewed runtime environment injection, without persisting values in image/config/evidence. No unsupported `_FILE` variable is introduced here.
- Option B/C managed service: separate environment namespace and workload identity, exact secret-version grants, access audit trail, no broad listing/export permission for normal operators. Human break-glass access requires named approval and a recorded incident reference. The secret-service recovery key is held separately from database backups.
- Rotation: create a least-privilege replacement; validate only with `pnpm release:credentials:check`; replace runtime version, restart/drain the single dispatcher, verify redacted success and provider kills, then revoke old key. On suspected leak revoke immediately, retain redacted evidence and revalidate. DB rotation coordinates affected role only. Pseudonym-key rotation changes linkage and respects existing 24h/7d retention; never retain raw addresses to rehash them.
- Backups include approved application data only, exclude env files, `/run/secrets`, sessions, SDK connection state and secret-store exports. Encrypt off-host data backups, separate encryption key custody, test restore in isolation. Retain rotation dates, key version IDs and actor references, never values. Audit, pentest and counsel packets receive synthetic data and redacted metadata only.

No production secret store is claimed configured. Missing account/custody decisions are explicit parts of `OWNER_INPUT_HOSTING`, not permission to deploy or open execution.
