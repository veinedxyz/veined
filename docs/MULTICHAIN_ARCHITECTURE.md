# Multichain architecture

Current domain `src/routing/`: Network/Asset/Catalog/Tool/Connection/RoutingQuote/RouteStep/Fee/ExecutionRequirement/RouteStatus, `NetworkCatalogProvider` and `RouteProvider`. Public provider ID `routing-core`; custom ONE provider `otherbridge-onebridge`. The product brand is Otherbridge. Real bridge/exchange protocol names are shown in the technical route review. The provider's step types are normalized to the neutral `bridge`/`exchange` types.

Public labels are normalized via `src/content/public-labels.ts`. Catalog tool IDs, quote binding, protocol identity, and fee amount/token/included status do not change. Provider service fees are shown as "Rota hizmet ücreti" / "Route service fee"; this wording does not mean that Otherbridge collects a fee. Review and Activity apply the same display protection to old/raw labels as well. Technical dependency and source records are in `docs/INTERNAL/THIRD_PARTY_NOTICES.md`; they are not carried over to the product screen.

`src/adapters/routing-core.ts` is the single upstream adapter. The official SDK v4 client is only on the server. `src/app/api/routing/route.ts` exposes limited same-origin POST read actions. The UI does not receive the upstream URL, API key, transactionRequest or SDK execution object. The upstream payload passes through a runtime schema; transaction calldata/typedData is stripped entirely.

The catalog is built from the current `/chains` + `/tools`. The bundled snapshot is only for the stale view. `src/routing/custom.ts` contains the explicit ONE entry and the BSC bootstrap identity that preserves the existing accepted ONE→BSC form at startup; it is not a mainstream support list. The current catalog uses the provider entry instead of the bootstrap BSC. In a ONE conflict, the custom adapter wins. A new custom network can be added to the merge registry; the routing transport is not changed. The old ONEbridge adapter, decoder, financial core, wallet and lifecycle files are preserved.

The initial view is the accepted ONE→BSC form. The network selector, mainstream form and catalog page open via dynamic import. Browser read connectors for the other VMs are loaded only upon an explicit connection request. The network list is virtualized with 72 px rows, with at most 10 options visible. All token data is searched; the DOM select shows at most the first 100 search matches, and address selection and the full address text are preserved. An EVM address is not automatically written into a non-EVM recipient field.

Public catalog: 5-minute cache/coalescing; public token catalogs: 5 minutes/at most 20 chains; there is no account-bound quote cache. A quote is read only on user request. Network/form/account/catalog changes break the quote and review binding. The submission gate is fixed at false/null. A stale network being visible, a connection being found, a quote being read and execution permission are separate states.

History: the new `otherbridge:routing-previews:v1` namespace does not mix with the original ONE history. QUOTE_PREVIEW records carry the public address/asset/steps and the quote binding. Adding an external hash is a hint; it does not mean that this application performed a submission. A current-context-bound provider status observation is visible only in memory for 30 seconds. Reload/import does not produce completion evidence.

A local build/start is not a production deploy. The measured HEAD and the final working tree SHA-256 inventory are in the handoff/package; no commit was created for this milestone. The performance comparison is made with a new isolated archive build of the same HEAD; no reset/clean is applied to the previous source tree.
