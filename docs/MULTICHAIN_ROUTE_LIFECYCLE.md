# Quote and observation lifecycle

Bridge discovery is only for pairs of different mainnet chains. The user selects the asset/address/amount/slippage and the 'Increase estimated amount received' or time preference. The official quote endpoint returns a single current quote for the selected metric; no fabricated alternatives are added. The domain array/comparison helper is ready for multiple real alternatives in the future. Because the exact wallet confirmation counts are unknown, a 'fewer confirmations' result is not fabricated. The exchange/bridge/protocol steps within a cross-chain quote are shown separately; no standalone Swap tab/V3 is enabled.

Quote binding: provider, source/destination chain, the two asset addresses, amount base units, the two native accounts, catalog generation, slippage, preference, wallet revision. An address/chain/amount/asset/preference change aborts the old request, increments the sequence number and closes the review. A pending old response is not published unless the binding and sequence match. A global EVM duplicate account event/reconnect also changes the revision. A catalog refresh/old tool/catalog older than 5 minutes or a quote older than 30 seconds invalidates the review. It does not change the old ONE MAX/race model.

Runtime quote validation checks the source/destination/asset/amount/address and slippage match, minimum<=expected, positive output and the current tool/chain identity. The real provider's `feeCollection` protocol is the single explicit internal exception; its name/step is visible. transactionRequest/calldata/typedData are stripped. Review: tool/steps, asset, expected/minimum, estimated cost/fee/gas, ETA, price impact including costs, approval targets, destination-signature notice and unknown balance/allowance/signature counts. These are not evidence of realized fees/transactions.

Storage is QUOTE_PREVIEW only. Nothing is written without Web Locks, a corrupt record is not overwritten, and an existing record is not dropped at the 40-record limit. The external source hash hint of the same record cannot be replaced with a conflicting hash. The original ONE storage key/runtime decoder/finality/recipient/token/amount evidence remains exactly as is.

External transaction observation is initiated by the user. The server status response must be bound to the context by source hash + the two chains + source amount/asset + the two addresses. COMPLETED additionally requires provider DONE/COMPLETED, destination tx/hash/chain/asset and a positive payout that meets the minimum. Partial/refund/failed are normalized separately; missing or mismatched metadata is UNKNOWN. A provider status observation becomes invalid after 30 seconds. Reload reads only the preview/hint; it does not restore completion. This new provider observation does not replace the ONEbridge decoder/finality G5 evidence.

The real execution lifecycle was not implemented in this milestone: there is no AWAITING_SIGNATURE/approve/execute/retry/refund automation. The submission buttons are disabled and there is no server write action schema.
