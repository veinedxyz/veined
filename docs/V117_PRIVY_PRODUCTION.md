## Exact owner action

1. Open [Privy Dashboard](https://dashboard.privy.io), select the owner-controlled production app **Otherbridge Production**, or create it. Use separate staging/development apps. Privy resources and settings are scoped to an app. Record a nonsecret app name, reviewer and review date.
2. Go to [Configuration → App settings → Basics](https://dashboard.privy.io/apps?page=settings&tab=basics), select **App ID**, and configure the public browser identifier as `NEXT_PUBLIC_PRIVY_APP_ID` through the production build configuration. Otherbridge validates `^[a-z0-9]{25}$`; a syntactically valid ID does not prove owner control. No Privy App Secret is required by Otherbridge's current client-only integration; do not copy/export/create one for this task.
3. In **Configuration → App settings → Domains → Allowed origins**, choose **Web & mobile web** and enter exactly **`https://otherbridge.io`** as the planned canonical origin. No path, wildcard, localhost or unrelated preview hostname. Domain ownership and final deployment are separate gates. `www.otherbridge.io` is a planned redirect to the apex; do not initialize the SDK there. Add `https://www.otherbridge.io` only if a separately reviewed plan actually serves the app there. `https://api.otherbridge.io` is a reserved API origin, not an SDK/browser app origin.
4. In **Configuration → App settings → Clients**, inspect all clients and their overrides. A React app does not require a separate client, but an existing client can override app defaults. Confirm production origins and wallet settings remain restricted in every applicable web client. Keep staging app/client origins separate. Do not enable HttpOnly auth cookies or login-session persistence for this connect-only milestone; the source pins `sessions.cookieWriteBehavior='never'`.
5. In the dashboard's **Authentication / Login methods** screen, enable **External wallets / Ethereum Wallet** only. Disable email, SMS, passkeys and **every** social/OAuth/Farcaster login provider. The current source additionally pins `loginMethods=['wallet']`, `appearance.walletChainType='ethereum-only'`, and uses `useConnectWallet`, not a login/SIWE flow. A dashboard setting must not be taken as permission to request a signature.
6. In **Wallets / Embedded wallets / wallet infrastructure**, disable automatic embedded wallet creation for both **Ethereum and Solana**. Current documented `createOnLogin='off'` means no wallet creation; source pins that value for both chains plus `showWalletUIs=false`. Do not enable smart wallets/account abstraction, funding/onramp, paymaster/gas sponsorship, Privy swap/bridge, embedded export or server-controlled wallet execution. Record OFF/NONE or **not configured**, not a guessed dashboard value.
7. In **Wallet infrastructure → Authorization keys** and signer/delegation settings, verify there is **no Otherbridge delegated/session signer or server execution authorization**. Current Privy signers use authorization-key quorums and user consent; this is not necessarily a single global OFF toggle. Record the absence of configured production execution signers, key quorums and attached signers with a redacted settings inventory. Do not generate a key, request consent, add a signer, sign an authorization or create a wallet to demonstrate absence.
8. Review CSP compatibility against the frozen source `src/proxy.ts` and `docs/PRIVY_SECURITY_BOUNDARY.md`. Preserve nonce-based production scripts/styles, exact WalletConnect verify/relay/registry origins and `connect-src https://auth.privy.io`; **do not permit `https://auth.privy.io` as a frame**. The embedded wallet iframe is deliberately excluded. Do not copy Privy's general full-feature CSP sample, which permits additional frames, inline styles and RPC domains used by broader features. Do not enable custom Privy auth domains or challenge/embedded features requiring new script/frame origins; such a change needs a separate reviewed security candidate.
9. Run `pnpm release:credentials:check --offline --out=<run>/Privy/credential-config.json`. The expected Privy status remains `OWNER_DASHBOARD_VERIFICATION_REQUIRED` until the real owner review evidence is accepted. Run `pnpm verify:safety`, `pnpm g7:safety`, `pnpm g7:pilot:safety` and review the release browser-security/CSP evidence. A configured public App ID and existing deterministic SDK/CSP tests are useful but are not a dashboard-state attestation.
10. Attach the evidence below without secrets, wallet addresses, sessions, cookies or API responses. `pnpm release:external-gates` must remain `EXECUTION_CLOSED / EXTERNAL_GATES_INCOMPLETE` while domain/Privy/audit/pentest/legal/release receipts are incomplete. Do not open the real wallet connection modal as part of this handoff; live wallet acceptance is outside this task's authorization.
